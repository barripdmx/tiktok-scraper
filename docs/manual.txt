MANUAL DEL PROYECTO TIKTOK
==========================

1. RESUMEN GENERAL
------------------
Este proyecto es un toolkit de scraping, analisis y visualizacion para TikTok.
Su objetivo es:

- guardar una sesion valida de TikTok;
- extraer videos de una cuenta o de un termino/hashtag;
- extraer comentarios de esos videos;
- analizar publicaciones y comentarios;
- clasificar sentimiento;
- enriquecer cuentas con fecha de creacion;
- generar informes HTML y grafos para Gephi.

La entrada y salida principal del sistema son archivos CSV y JSON.


2. ESTRUCTURA DEL PROYECTO
--------------------------
Raiz del proyecto:

- menu.py
  Lanzador principal con menu por fases.
- requirements.txt
  Dependencias de Python.
- README.md
  Resumen basico del proyecto.

Carpetas importantes:

- src/scrapers
  Scripts que descargan datos de TikTok.
- src/analysis
  Scripts que procesan y analizan CSVs.
- src/visualization
  Scripts que convierten resultados en HTML o GEXF.
- src/utils
  Utilidades compartidas y enriquecimiento de cuentas.
- data
  Salida principal de scrapers: cookies, logs, CSV y JSON.
- outputs/graphics
  Graficas, informes HTML y resultados analiticos.
- drivers
  Perfiles persistentes de Chromium/Playwright.
- config
  Variables de entorno como claves API.
- tests
  Pruebas auxiliares.
- archive
  Scripts antiguos o experimentales; no forman parte del flujo principal.


3. FLUJO DE TRABAJO RECOMENDADO
-------------------------------
Flujo normal del programa:

1. Guardar sesion.
2. Extraer videos.
3. Extraer comentarios.
4. Analizar publicaciones o comentarios.
5. Clasificar sentimiento si hace falta.
6. Enriquecer cuentas con fecha de creacion.
7. Graficar fechas de creacion o generar informe HTML.
8. Exportar GEXF para Gephi si se quiere analizar red.

Encadenado tipico:

- cuenta TikTok -> CSV de videos
- CSV de videos -> CSV de comentarios
- CSV de comentarios -> graficas / sentimiento / cuentas dominantes
- CSV de cuentas dominantes -> CSV enriquecido con fecha de creacion
- CSV enriquecido -> graficas de fechas de creacion

5. FASE 0 - AUTENTICACION
-------------------------
Archivo: src/scrapers/1-guardar_sesion.py

Objetivo:
Abrir TikTok en un navegador real, permitir login manual y guardar la sesion.

Funcionamiento:

1. Calcula rutas base del proyecto.
2. Crea drivers/playwright_auth si no existe.
3. Lanza Chromium con Playwright en modo visible.
4. Abre https://www.tiktok.com/login
5. Espera a que el usuario inicie sesion manualmente.
6. Guarda el storage state en:
   drivers/playwright_auth/tiktok.json
7. Extrae cookies y las exporta en:
   data/tiktok_cookies.json

Por que es importante:

- los scrapers reutilizan estas cookies;
- reduce bloqueos;
- evita tener que loguearse en cada ejecucion.


6. UTILIDADES COMPARTIDAS
-------------------------
Archivo: src/utils/tiktok_utils.py

Es el modulo comun reutilizado por los scrapers.

Bloques principales:

6.1. Fechas desde video_id
- get_date_from_video_id(video_id)
  Obtiene fecha aproximada usando el timestamp embebido en el ID.
- estimate_date_from_id_simple(video_id)
  Fallback aproximado si el metodo exacto falla.
- is_likely_in_date_range(...)
  Filtro previo con margen.
- is_in_date_range(...)
  Filtro exacto por fecha.

Uso:
Permite descartar videos fuera de rango sin visitar todos.

6.2. Manejo de URLs
- normalize_tiktok_url(url)
- extract_video_id_from_url(url)
- extract_username_from_url(url)
- is_valid_video_url(url)

Uso:
Normaliza enlaces y extrae identificadores reutilizados en todo el sistema.

6.3. Conversion de metricas
- parse_count(text)

Uso:
Convierte textos como 1.2M o 500K a enteros.

6.4. Helpers Playwright
- human_scroll(page)
- accept_cookies_banner(page)
- handle_verification(page)
- detect_end_of_results(page)

Uso:
Reducen problemas de scraping, banners y verificaciones.

6.5. Contexto persistente y cookies
- load_cookies(context, cookies_path)
- save_cookies(context, cookies_path)
- ensure_context(...)

Uso:
Lanza Chromium persistente con perfil, cookies y algunos ajustes antibot.

6.6. Recoleccion de URLs
- collect_video_urls(...)

Uso:
Hace scroll en paginas de busqueda/hashtag y devuelve URLs de videos.


7. SCRAPER DE USUARIO
---------------------
Archivo: src/scrapers/1_tiktok_scraper_user.py

Objetivo:
Descargar todos los videos de una cuenta concreta.

Salida:

- data/user_<usuario>_videos.csv
- data/user_<usuario>_videos.json
- data/scraper_user.log

Funcionamiento interno:

7.1. Configuracion
Define:

- carpeta data;
- cookies;
- perfil Playwright;
- modo headless;
- numero maximo de scrolls;
- pausas y logging.

7.2. ensure_context()
Wrapper sobre la utilidad compartida para usar el perfil y cookies de este scraper.

7.3. collect_user_videos(context, username)
Hace el trabajo de descubrimiento:

- abre el perfil;
- intenta extraer datos del usuario desde el JSON embebido;
- obtiene followers, likes, bio, verificacion y fecha de creacion de cuenta;
- entra en la pestana de videos;
- hace scroll y recoge URLs validas del perfil;
- se detiene cuando deja de encontrar videos nuevos.

7.4. extract_metadata(context, url, username)
Abre cada video y extrae:

- video_id y URL;
- descripcion;
- fecha del video;
- duracion y dimensiones;
- likes, vistas, compartidos, comentarios y guardados;
- datos del autor;
- musica;
- hashtags;
- menciones.

Incluye un fallback HTML por si el JSON embebido no trae metricas.

7.5. Filtro por fechas
El script permite:

- un prefiltro por ID del video;
- una verificacion posterior con la fecha real del video si esta disponible.

7.6. save_results()
Guarda un JSON rico y un CSV estandarizado.

Resumen:
Es el scraper base para estudios de una cuenta concreta.


8. SCRAPER DE HASHTAG / TERMINO POR API
---------------------------------------
Archivo: src/scrapers/2_tiktok_scraper_hastag_api.py

Objetivo:
Buscar videos por termino o hashtag usando llamadas a la API interna de TikTok
ejecutadas desde el navegador.

Ventaja principal:
Es mucho mas rapido que el scraping por scroll del DOM.

Salida:

- data/<label>_videos_api.csv
- data/<label>_videos_api.json
- data/scraper_hastag_api.log

Funcionamiento interno:

8.1. api_fetch(page, url)
Ejecuta fetch() dentro del navegador. Asi aprovecha firma, cookies y sesion
del propio contexto web.

8.2. get_challenge_id(page, tag)
Abre /tag/<tag> y extrae el challengeID desde el JSON embebido.

8.3. collect_from_search(page, keyword)
Pagina los resultados de busqueda general.

8.4. collect_from_challenge(page, challenge_id, tag)
Pagina la API de hashtag/challenge.

8.5. item_to_row(item, video_url)
Convierte la respuesta de API al formato CSV del proyecto.

8.6. matches_strict(query_terms, desc, hashtags_str)
Filtro estricto literal para asegurar que el termino realmente aparece.

8.7. Post-procesado final
Aplica:

- deduplicacion por video;
- filtro por fecha;
- filtro estricto;
- guardado final en CSV/JSON.

Uso recomendado:
Cuando se quiere cobertura rapida de un tema, palabra o hashtag.


9. SCRAPER DE COMENTARIOS CONCURRENTE
-------------------------------------
Archivo: src/scrapers/3_tiktok_scraper_comentarios_mobile.py

Objetivo:
Extraer comentarios de muchos videos de forma concurrente.

Entrada:
Un CSV de videos con columna video_url.

Salida:

- data/<base>_comentarios_mobile.csv
- data/<base>_mobile_checkpoint.json
- data/logs/comentarios_mobile_<timestamp>.log

Caracteristicas clave:

- varios workers concurrentes;
- un contexto Playwright por worker;
- checkpoint de videos ya procesados;
- escritura segura en CSV con asyncio.Lock;
- recuperacion parcial si se interrumpe.

Funcionamiento interno:

9.1. Utilidades y logging
- _TeeIO
  Duplica la salida a consola y a log.
- init_logging() / close_logging()
  Preparan el log de la sesion.
- seleccionar_csv()
  Pide el CSV de entrada.
- cargar_urls_desde_csv()
  Extrae las URLs de video desde el CSV.

9.2. create_context(pw, worker_id)
Cada worker usa su propio perfil Chromium para evitar bloqueos entre procesos.

9.3. extract_comments(context, url, worker_id, limit)
Es el corazon del scraper:

- abre el video;
- abre el panel de comentarios;
- escucha respuestas de red a /api/comment/list/;
- hace scroll continuo del panel;
- expande replies cuando puede;
- recoge comentarios y replies interceptados;
- convierte todo al formato de salida.

Campos generados:

- video_id
- video_url
- username
- comment_id
- fecha
- autor_nombre
- autor_handle
- texto
- likes
- aweme_id_api
- is_reply
- parent_comment_id

9.4. worker(...)
Toma videos de una cola, llama a extract_comments, guarda resultados y actualiza
el checkpoint.

9.5. main()
Coordina:

- lectura del CSV;
- reanudacion desde checkpoint;
- numero de videos a procesar;
- limite de comentarios por video;
- numero de workers;
- resumen final de cobertura.

Importante:
El propio script avisa que la cobertura no siempre es total en videos muy grandes.

11. ANALITICA DE COMENTARIOS
----------------------------

Objetivo:
Analizar comentarios, actividad de la comunidad y sentimiento local con IA

Entrada:
CSV de comentarios.

Salidas:

- outputs/graphics/<proyecto>/comentarios
- outputs/graphics/<proyecto>/polaridad_ia

Bloques funcionales:

11.1. Configuracion y rutas

11.2. generar_nubes(df, ...)

- top comentaristas por likes;

11.4. generar_analisis_temporal(df, ...)

12. SENTIMIENTO CON GEMINI
--------------------------
Archivo: src/analysis/analizar_sentimiento_gemini.py

Objetivo:
Clasificar comentarios con Gemini en lotes y guardar un CSV reutilizable.

Entrada:
CSV de comentarios.

Salida:

- CSV original + sufijo _con_sentimiento_gemini.csv
- checkpoint _gemini_checkpoint.json
- graficas en outputs/graphics/<proyecto>/polaridad_ia

Funcionamiento:

12.1. Carga de API key
Busca GEMINI_API_KEY en config/.env. Si no existe, la pide por ventana.

12.2. clasificar_lote()
Manda lotes de comentarios a Gemini y exige JSON con etiquetas POS/NEG/NEU.

12.3. Reintentos y fallback
Si hay errores 5xx:

- usa backoff exponencial;
- reintenta varias veces;
- puede pasar de gemini-flash-lite-latest a gemini-2.5-flash.

12.4. Checkpoint
Guarda el avance para no perder lotes ya procesados.

12.5. Graficas finales
Genera:

- distribucion de sentimiento;
- evolucion acumulada;
- top comentarios positivos y negativos;
- top usuarios positivos y negativos.

Uso:
Conviene cuando se quiere una clasificacion externa con Gemini y conservar
el resultado en CSV para futuros procesos.


13. COMPARATIVA ENTRE CUENTAS
-----------------------------
Archivo: src/analysis/comparativa_usuarios.py

Objetivo:
Comparar el comportamiento de los mismos usuarios comentando en varias cuentas.

Funcionamiento:

1. Pide varios CSV de comentarios.
2. Deduce la cuenta destino a partir del nombre del archivo.
3. Fusiona todos los comentarios.
4. Aplica un sentimiento lexico sencillo.
5. Calcula sentimiento neto por usuario y cuenta:
   positivos - negativos
6. Escoge los usuarios mas polarizados/activos.
7. Genera una grafica comparativa agrupada.

Salida:

- outputs/graphics/comparativa_sentimiento_usuarios.png

Uso:
Sirve para detectar usuarios muy alineados o muy criticos segun la cuenta.

15. GRAFOS GEXF
---------------
Hay dos scripts relacionados con redes.

15.1. crear_gexf.py
Objetivo:
Crear una red simple comentarista -> autor del video.

Entrada:
Uno o varios CSV de comentarios.

Proceso:

- carga filas;
- ignora autocomentarios;
- cuenta cuantas veces un autor_handle comenta a un username;
- construye nodos con estadisticas;
- guarda un GEXF con peso por numero de comentarios.

Salida:
Archivo .gexf en el mismo directorio del primer CSV.

Uso:
Es la opcion del menu para abrir luego en Gephi.

15.2. grafo_comentarios.py
Objetivo:
Construir un grafo mas fino donde:

- comentario directo -> apunta al autor del video;
- reply -> apunta al autor del comentario padre.

Ademas añade:

- peso;
- videos_unicos;
- primer comentario;
- ultimo comentario;
- rol del nodo: autor_video, comentarista o ambos.

Uso:
Es mas detallado que crear_gexf.py, aunque no esta conectado directamente al menu.


16. FECHAS DE CREACION DE CUENTAS
---------------------------------
Esta parte se divide en tres scripts.

16.1. src/utils/extraer_fechas_creacion_cuentas.py
Objetivo:
Consultar perfiles de TikTok y extraer fecha de creacion de cuenta.

Como funciona:

- normaliza usernames;
- descarga la pagina del perfil;
- extrae el JSON de hidratacion;
- intenta leer user.createTime;
- si no existe, estima desde user.id >> 32;
- guarda CSV y JSON con metadatos de cuenta.

Uso:
Sirve para consultar un conjunto de cuentas manualmente.

16.2. src/utils/enriquecer_csv_fechas_creacion.py
Objetivo:
Enriquecer un CSV grande usando cuentas unicas.

Entrada:
Un CSV con columna de handles, por defecto autor_handle.

Como funciona:

- extrae handles unicos;
- carga un lookup parcial ya existente si lo hay;
- consulta solo cuentas pendientes;
- guarda incrementalmente el lookup;
- fusiona el lookup con el CSV original;
- genera un CSV enriquecido.

Salidas:

- <base>_lookup_fechas_creacion.csv
- <base>_enriquecido_fechas_creacion.csv

Uso:
Es la opcion 10 del menu. Es el paso previo para estudiar antiguedad de cuentas.

16.3. src/visualization/graficar_fechas_creacion_cuentas.py
Objetivo:
Graficar la distribucion temporal de creacion de cuentas.

Entrada:
Uno o varios CSV enriquecidos.

Escenarios:

- un solo CSV -> grafica simple por mes;
- varios CSV de sentimientos -> barras apiladas, barras 100% y boxplot.

Salidas:
Carpeta fechas_creacion junto a los CSV de entrada.

Graficas posibles:

- fechas_creacion_por_mes.png
- fechas_creacion_apilado.png
- fechas_creacion_100pct.png
- edad_cuenta_boxplot.png
- resumen_fechas_creacion.csv

Uso:
Sirve para detectar si grupos de cuentas parecen recientes o coordinados.

20. RECOMENDACIONES DE USO
--------------------------
- Ejecutar primero 1-guardar_sesion.py.
- No mezclar CSVs con estructuras distintas dentro del mismo analisis.
- Para comentarios masivos, usar el scraper concurrente del menu.
- Para informes HTML, generar antes la analitica de publicaciones.
- Para estudiar bots o coordinacion:
  1. analitica_comentarios
  2. exportar cuentas dominantes
  3. enriquecer fechas de creacion
  4. graficar fechas de creacion
- Revisar data/logs cuando un scraping falle o se quede corto.


21. RESUMEN FINAL DEL FUNCIONAMIENTO
------------------------------------
El programa completo se comporta como una tuberia de datos:

- primero autentica y prepara sesion;
- despues recolecta videos o comentarios;
- luego transforma esos datos en CSV estandarizados;
- a partir de esos CSV genera analisis estadisticos, sentimiento y visualizaciones;
- finalmente permite exportar resultados en formatos de consumo humano
  (PNG, TXT, HTML) o de analisis de red (GEXF).

La parte mas importante del flujo actual es:

- menu.py
- 1-guardar_sesion.py
- 1_tiktok_scraper_user.py o 2_tiktok_scraper_hastag_api.py
- 3_tiktok_scraper_comentarios_mobile.py
- analitica_publicaciones.py / analitica_comentarios.py
- analizar_sentimiento_gemini.py
- enriquecer_csv_fechas_creacion.py
- generar_informe_html.py
- crear_gexf.py
